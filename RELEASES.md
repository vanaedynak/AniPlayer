# Выпуски: новые версии, стабильная, откат

## Коротко

- Каждая выпущенная версия — отдельный релиз на GitHub: `v1.0.61`, `v1.0.62`… Старые не стираются.
- Приложения (Windows, iPad, Android) берут ту версию, у которой на GitHub значок **Latest**.
- Одну версию можно отметить **⭐ стабильной**: это проверенная версия, к которой удобно возвращаться.
- Push в `main` теперь только **собирает** приложение (проверка, файлы лежат в Actions → артефакты).
  До пользователей версия доходит только по кнопке «Выпустить».
- В лаборатории (`"lab": true` в `flavor.json`) всё как раньше: каждый push сразу выпускается.

## Где кнопки

**Вариант 1 — окно на компьютере:** двойной щелчок по `lab-tools\Выпуски.cmd`.
Там список версий и кнопки. Нужен вход в GitHub CLI (`gh auth login`, один раз).

**Вариант 2 — на сайте GitHub:** Actions → **Build apps** → **Run workflow**, в поле `action` выбрать:

| action | что делает | поля |
|---|---|---|
| `publish` | собирает и выпускает новую версию | `notes` — что нового; `from` — пусто, или `v1.0.57` / `stable`, чтобы собрать старую версию заново |
| `rollback` | удаляет самую новую версию, значок Latest переходит на предыдущую | — |
| `stable` | ставит ⭐ на версию (с прежней снимает) | `version` — пусто = текущая |

Выпуск идёт 15–20 минут (собираются iPad, Android и Windows), откат и отметка — около минуты.

## Как забрать работу из лаборатории

1. `lab-tools\Объединить проекты.cmd` → «Забрать в основной проект» (проверит сборку и отправит в `main`).
2. Push в `main` соберёт приложение, но **не выпустит** его. Можно скачать артефакты и проверить.
3. Понравилось — «Выпустить новую версию». Появится `v1.0.N` с пометкой Latest, приложения обновятся.
4. Пожили с ней, всё хорошо — «Отметить выбранную стабильной».

## Как откатиться

**«Откатить последнюю»** удаляет самую новую версию, и Latest переходит на предыдущую. После этого:

- новые установки и приложения, которые ещё не обновились, получат предыдущую версию;
- приложения, которые **уже поставили** удалённую версию, останутся на ней: обновление умеет только
  повышать номер, назад само не идёт.

Чтобы вернуть старый код **всем**, включая уже обновившихся, нажмите **«Выпустить выбранную заново»**
(или `publish` с `from: v1.0.57` / `from: stable`). Код той версии соберётся под новым, большим номером,
и все получат его как обычное обновление.

Удаляйте версии кнопкой, а не вручную на сайте: кнопка заодно обновляет служебную копию (см. ниже).
Если всё же удалили вручную — Windows всё равно перейдёт на предыдущую, а копию поправит следующий выпуск.

## Служебный релиз `latest`

Рядом с версиями лежит пре-релиз `latest` («Служебная копия … (не трогать)»). Это копия текущей версии для
приложений на iPad и Android, собранных до 7 ноября 2026: они ищут обновления только по этому имени.
Пре-релиз никогда не получает значок Latest, поэтому выбору версии он не мешает. Когда на всех устройствах
стоит версия новее 7 ноября, его можно перестать вести.

## Как это устроено (для разработчика)

- `.github/workflows/build.yml` — сборка и кнопки; `.github/scripts/releases.sh` — работа с релизами.
- Номер версии — `1.0.<номер запуска Build apps>`, всегда растёт. Пропуски номеров нормальны.
- Windows обновляется с `releases/latest/download/latest.yml`, iPad/Android спрашивают API `/releases/latest`.
- При откате git-тег удалённой версии остаётся, поэтому её можно собрать снова через `from`.
- Первый выпуск по новой схеме сам сохранит прежнюю сборку (`Anyflow build 59`) как `v1.0.59`,
  так что откатиться будет куда.
